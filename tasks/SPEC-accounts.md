# Spec: Учётные записи и синхронизация избранного

## Objective

Добавить полноценную авторизацию (вариант 3): регистрация, вход, сессии браузера `«запомнить меня»`, выход. Залогиненный пользователь получает:
- синхронизацию **избранного** (звёздочки треков) между устройствами;
- синхронизацию **настроек плеера** (фильтры, shuffle/repeat, громкость, chip mode и другие параметры из `state`, сохраняемого в `ayPlayer_state`).

Гости работают как сейчас: избранное/настройки только в localStorage браузера. При входе данные браузера **сливаются** с данными аккаунта (merge).

## Tech Stack

- PHP 7.4+ (хостинг уже PHP: `index.php`, `api/counter.php`)
- Без БД — JSON-файлы на диске в `api/` (паттерн уже используется `ayPlayer_counter.json`)
- `password_hash()` / `password_verify()` (PASSWORD_BCRYPT)
- Сессия PHP (cookie `PHPSESSID`) + relogin токен для «запомнить меня»
- Клиент: vanilla JS (ES5-стиль как в проекте, `var`/`function`), fetch
- Сервис воркер `sw.js` — network-first для `/api/` уже есть, подходит

## Commands

- Запуск локально: `php -S localhost:8080` (из корня)
- Проверка PHP: `php -l api/auth.php`
- Проверка JS: `node --check player/ayPlayer.js` (после правок)
- Сборки плейлиста/карт: без изменений (эта фича их не трогает)


## Code Style

Паттерн проектной кодировки (ES5-стиль как в `init.js` / `counter.php`):

```js
var API = 'api/auth.php';
function doLogin(form) {
    fetch(API + '?action=login', {
        method: 'POST',
        body: new URLSearchParams(form)
    }).then(function(r){ return r.json(); }).then(function(res){
        if (res.ok) AYPlayer.applyAccount(res); else showError(res.error);
    });
}
```

PHP — как в `counter.php`: `header('Content-Type: application/json; charset=utf-8')`, проверка `$_SERVER['REQUEST_METHOD']`, JSON-файлы через `file_get_contents`/`file_put_contents` с `LOCK_EX` и `is_writable(__DIR__) ? __DIR__ : sys_get_temp_dir()`.

## Testing Strategy

- Ручной сценарий на локальном PHP-сервере (спека не требует тест-фреймворка; в проекте их нет).
- Сценарии: регистрация → вход → звёздочка → перезагрузка → звезда на месте; вход на «другом устройстве» (другой браузер/инкогнито) → синхронизировано; выход; гостевой режим без изменений.
- `php -l` для новых php-файлов, `node --check` для JS.
- Проверка лаут-флов: неправильный пароль, лимит попыток, слабый пароль, дубликат ника.

## Boundaries

- **Always**: `password_hash()` для паролей; никогда не логировать/отдавать хеши; `LOCK_EX` при записи JSON; валидация длин (ник ≤ 32, пароль ≥ 6); `final$` экранирование.
- **Ask first**: добавление новых npm-зависимостей (не нужны); изменение `sw.js` кэш-стратегии (не требуется — network-first уже есть); любые изменения в обработке реальных данных плейлиста.
- **Never**: коммитить `api/users.json`, `api/favorites.json`, `api/auth_fail.json`, хеши паролей; писать пароли в openquery/plaintext; доступа к чужим accounts.

## Success Criteria

1. Гость видит меню сверху: `about help login`. Вход открывает модалку «Вход/Регистрация» (вкладки).
2. Регистрация с ником + паролем (≥6 символов) создаёт аккаунт; дубликат ника отклоняется. Ошибки показываются в модалке.
3. После входа меню показывает ник и пункт «Выйти»; `auth.php?action=me` возвращает профиль.
4. Избранное: `toggleFavorite()` после входа сохраняет и локал (мгновенно) и на сервер. Перезагрузка / другое устройство (с тем же логином) показывают те же звёзды.
5. Настройки: `xe()` (сохранение state) `reverse` — при входе объединяются (account приоритет, браузерные при отсутствии в аккаунте). Merge применяется к плееру.
6. «Запомнить меня» переживает закрытие браузера (relogin token); без него — до конца сессии.
7. Лимит попыток: 5 неудач / 15 мин на IP → «попробуйте позже».
8. Выход очищает локальный `ayPlayer_state`/favorites? Нет — remainder локально, только сессия завершается (merge на след. вход).
9. Гостевой режим и вся логика без входа работают идентично прежнему.
